# 这是一份给我义子的礼物 (AGiftforMyFosterSon) v0.1.5 — 测试指南

Brotato 1.2.0.1 (Primal Dread) 合作模式道具赠送 mod。显示名「这是一份给我义子的礼物」,技术 ID 为 AGiftforMyFosterSon-Mod(ModLoader 强制 ID 为「命名空间-名称」双段格式且仅限 ASCII 字符;namespace 与 authors 均不含个人信息,发布时工坊页面标题用中文名)。
本版本为**未实机验证的初版**（开发机没有 Steam），代码已通过 Godot 3.6 + 游戏 API 桩工程编译验证（3/3 通过），并内置了完整的运行时诊断——你的第一轮实测日志会直接告诉我所有需要适配的点。

**v0.1.2 更新**：完成工坊订阅榜 Top25 热门 mod 全量源码审计（详见[生态兼容性审计](生态兼容性审计.md)），新增**直接调用回退机制**——任何 mod 断掉 `_ready` 继承链（如 SteamCouchCoop 联机 mod）时赠送功能依然可用。

**v0.1.1 更新**：对照 ShareWithYourBro / Coop Trading / ZloiDed-TradeMod 三个前辈 mod 的全部已知 bug 做了 22 项审计，新增：特殊道具黑名单（芹菜茶/诱饵/孔雀）、与 ItemSelling mod 共存逻辑、focus/hide 冗余刷新挂载点、按钮构建三级回退、悬空引用清理，并在 manifest 声明与同类交易 mod 互斥。

## 一、安装（本地测试，无需上传工坊）

1. 找到 Steam 工坊目录：`<Steam安装盘>:\Program Files (x86)\Steam\steamapps\workshop\content\1942280\`
   （不确定位置就在 Steam 里右键 Brotato → 管理 → 浏览创意工坊，或随便订阅一个 mod 看下载路径）
2. 在该目录下**新建一个任意名字的文件夹**，比如 `giftbro-test`
3. 把 `AGiftforMyFosterSon-Mod-v0.1.5.zip` 放进去（保持 zip 原样，不要解压）
4. 启动 Brotato，主菜单若弹出 mod 加载提示 / 无报错即成功一半

## 二、测试步骤（按顺序）

前置：开一局**本地合作 2 人**（第二个玩家用手柄或键盘 P2 即可），打到第一个商店。

| # | 操作 | 预期 |
|---|---|---|
| 1 | 进入商店，购买任意道具 | 正常 |
| 2 | 点击自己已拥有的道具（弹出道具详情） | 弹窗里出现**「送给队友」**按钮（取消按钮上方）；**合成/回收按钮消失** |
| 3 | 点「赠送」 | 自己失去该道具，P2 获得，双方面板属性刷新，背包列表刷新 |
| 4 | 把道具买到上限，再让 P2 也买满，重复步骤 2 | P2 的赠送按钮**灰显**，悬停显示上限提示 |
| 5 | 拿一件武器点开弹窗 | **完全原版行为**（含 1.2 新的机械化/合成按钮，重点验证机械化可用！） |
| 6 | 赠送「长胡子的婴儿」类带弹射物效果的道具 | 不崩溃、角色贴图正常 |
| 7 | 赠送后继续打完一波再进商店 | 道具**不会回退**到原主人 |
| 8 | 3~4 人局（见下方多人矩阵） | 每个队友一个赠送按钮，标签带**角色名**，如「送给 小土豆 (P3)」 |
| 9 | 手柄操作弹窗 | 上下键能在 赠送按钮↔取消 间切换焦点 |
| 10 | 尝试赠送芹菜茶/诱饵/孔雀 | 弹窗**不出现**赠送按钮（特殊道具黑名单，防平衡/逻辑问题） |

### 多人按钮正确性矩阵（v0.1.5 重点，开 3~4 人局逐格核对）

按钮标签现在带目标玩家角色名——**点之前先核对标签指向的角色是不是你要送的人**，这是发现"按钮指向错人"类 bug 的最快手段。日志会同步记录每个弹窗的按钮映射（`diag: popup of P1 -> gift buttons for [1, 2]`），实测后对照：

| 视角 | 应出现的按钮 | 不应出现 |
|---|---|---|
| P1 的弹窗 | 送给 [P2角色名] (P2)、送给 [P3角色名] (P3)、送给 [P4角色名] (P4) | 任何指向 P1 自己的按钮 |
| P2 的弹窗 | 送给 (P1)、送给 (P3)、送给 (P4) | 指向 P2 的按钮 |
| P3 的弹窗 | 送给 (P1)、送给 (P2)、送给 (P4) | 指向 P3 的按钮 |
| P4 的弹窗 | 送给 (P1)、送给 (P2)、送给 (P3) | 指向 P4 的按钮 |

交叉赠送验证（4 人局，每格做完看双方面板+日志 `gift: ... P? -> P? ok`）：

- [ ] P1 → P3：P3 获得道具与属性，P1 失去
- [ ] P3 → P1：反向同样成立
- [ ] P2 → P4、P4 → P2：交叉成立
- [ ] 只把 P3 买满上限：所有人的弹窗里**只有指向 P3 的按钮灰显**，指向 P2/P4 的不受影响
- [ ] 同一道具，P1 送给 P2 后，P2 的弹窗里能再把它送给 P3（链式转赠）
- [ ] 日志中 4 个弹窗各出现一行 `diag: popup of P? -> ...`，映射与上表一致

## 三、DLC 测试（Primal Dread / All Pain No Gain / Abyssal Terrors）

原理：DLC 道具与本体道具走完全相同的 ItemData 路径，AGiftforMyFosterSon 代码不引用任何 DLC 专有类，**无 DLC 也能正常运行**。DLC 测试重点是新效果类型是否踩到赠送的边界情况。

| # | 测试项 | 关注点 |
|---|---|---|
| D1 | 不启用任何 DLC，重复主清单 1-9 | mod 必须无 DLC 依赖（代码层面已保证，验证即可） |
| D2 | Primal Dread 40 个新道具里分类抽测各 5 个：普通属性/诅咒/带弹射物/唯一/带进化效果 | 转移后属性刷新正确、不崩溃 |
| D3 | 带 Evolution（进化）效果的道具赠送 | 新属性重算是否跟随（1.2 最大风险点） |
| D4 | 已机械化武器的玩家赠送/获赠道具 | 机械化状态与武器数据不受污染 |
| D5 | All Pain No Gain 角色（求痛得痛/Wounded）持有道具时赠送 | SWYB 1.1.2 曾为该角色专门修过兼容 |
| D6 | 各 DLC 的"下一波生效"类道具 | 必须被黑名单挡住，不出现赠送按钮 |

加速手段：
- 装上 **Cheat Menu** mod（Kandro78-CheatMenu，已审计共存安全）直接把 DLC 道具刷进背包，省去每局刷商店
- 用 Item Set / 干净存档开新局，避免其他 mod 内容污染判断（modded 道具会残留在解锁/存档里）
- 每次赠送成功日志会记 `gift: item 'item_xxx' P1 -> P2 ok`——DLC 道具 my_id 出现在日志里 = 该道具路径已验证

想看 DLC 内部实现（可选，用于精确适配）：GDRE Tools 里**同时选中主 `Brotato.pck` 和 DLCs 目录下的 pck** 一起 Recover Project，跨 pck 引用才能正确解析。

## 四、日志收集（重要！无论成败都发我）

日志文件：`%APPDATA%\Brotato\logs\godot.log`
（资源管理器地址栏粘贴 `%APPDATA%\Brotato\logs` 回车即到）

把这个文件整个发回来即可。里面有价值的行：

- `AGiftforMyFosterSon-Mod:Main loading/loaded` — mod 是否加载
- `compat: ...` — RunData / base_shop / Utils 各项 API 是否存在（我据此精确适配）
- `diag: popup button layout -> [...]` — 你这版游戏商店弹窗的真实按钮清单（我据此核对 UI 注入点）
- `gift: item 'xxx' P1 -> P2 ok` — 每次赠送成功记录
- 任何 `SCRIPT ERROR` / `AGiftforMyFosterSon-Mod` 相关报错

## 五、如果完全没反应/报错

按优先级排查：
1. godot.log 里搜 `AGiftforMyFosterSon`——连 loading 都没有 = mod 没被加载（检查 zip 放置路径）
2. 有 `SCRIPT ERROR: Parse Error` 指向 AGiftforMyFosterSon 的 .gd = 游戏 1.2 改了脚本签名，把日志发我，一般 10 分钟内能出修复版
3. 按钮没出现但无报错 = 弹窗成员名变了，diag 日志会暴露，同样发我

## 七、发布到创意工坊（实测通过后）

**前置要求**：
1. Steam 账户已购买 Brotato，且历史**消费满 $5**（解锁工坊上传权限）
2. Zip 结构须为 `mods-unpacked/AGiftforMyFosterSon-Mod/` 根目录——当前发行包已合规，无需调整

**发布步骤**：
1. Steam 库 → 右键 Brotato → 属性 → **Betas** 标签 → 切换到 `modding` 分支（自动下载官方 mod 上传器）
2. **从 Steam 启动** Brotato（不能直接双击 exe），进入 mod 上传器
3. 选择 zip → 填名称/描述（注明兼容 Brotato 1.2.0.1 / Primal Dread + GML 6.3+）→ 上传 **512×512** 图标（画廊图建议 637×358）
4. 发布后默认 **Hidden（仅自己可见）**，先自测订阅一遍，再在工坊页面手动改 Public
5. 后续更新：上传器里填**原工坊 ID** 覆盖上传，manifest 版本号递增

**合规红线**（近期 3 个同类 mod 被 Steam 下架，务必注意）：
- 上传包里**不得包含原游戏代码**——AGiftforMyFosterSon 两个扩展脚本全部自研、零游戏代码，这是当初防御式设计的额外好处
- 本地反编译的 Godot 工程（含游戏代码）**不得公开托管**，GitHub 仓库必须私有（本项目 stub-check 桩工程全为自写桩，可以公开）
- 描述中注明致敬 ShareWithYourBro 并 @CodeCooker（社区礼节）
- 发布前建议把 zip 拿到 Brotato Modding Discord #modding-help 给社区过目，确认打包惯例无变化

**发布后维护节奏**（前辈 mod 的死亡率教训）：
- 游戏每次更新当天看一眼 `compat:` 日志是否报 MISSING，当天出适配版
